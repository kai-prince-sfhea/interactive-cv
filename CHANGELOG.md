# Changelog

## 0.0.4 — diagnostic privacy follow-up — 14 October 2026

- Refuse unsupported metadata/import/export fields without echoing their supplied
  names or duplicate/relation record IDs. Import prevalidation uses structural
  positions instead of arbitrary nested keys or consent-sidecar record IDs in
  error messages; filesystem and malformed export-URL errors use safe remedies.
- Preserve catalogue content, explicit permissions, source status, field bounds
  and document exports; no catalogue/interchange migration is required.
- Use the published issue link and consistent owner-qualified update command.

### 0.0.3 public-source preparation

Portable local setup/lifecycle instructions, explicit option/support/migration
boundaries, development-AI disclosure and full-suite reproduction limits.
Private/local environment defaults are ignored as housekeeping. Invalid enum
and public-record-type diagnostics name the contract without echoing rejected
metadata values. The experimental version remains 0.0.3; source publication,
supported release, real-data use and deployment are separate decisions.
Documented whole-namespace metadata replacement and complete override syntax;
catalogue schema permits relative dot/parent components subject to the existing
runtime document/project confinement checks.
Use Quarto's documented project offset and Pandoc's input working directory for
catalogue/link paths, avoiding the independently observed Windows input/root
encoding mismatch for a Latin-1 project directory.

## 0.0.3 — validation, navigation and filtering follow-up

Order-independent skill hierarchy limits; strict public-model references,
collections and decision dates; consistent static-path validation; linked output
root refusal in the audit CLI. Same-page preview links close the dialog and focus
the destination; embedded previews avoid nesting main landmarks. Filtering compiles query tokens once and avoids unchanged
status, class and history writes. Performance evidence is synthetic component
evidence, not a whole-website speedup or accessibility-conformance claim.

## 0.0.2 — experimental core completion

Public-only interchange import and literal JSON catalogues; reference schema,
exact source qualifications/facts, optional readable anchors; selected Word and
structured PDF print previews; explicit whole-output/privacy/withdrawal auditing.
Real data, manual accessibility/office acceptance, direct PDF/UA, advanced graph,
temporal, language and AI adaptation remain separate gates.

## 0.0.1 — local experimental CV-0

Explicit public YAML records, eleven ontology types plus supporting assertions,
native static index/detail rendering, publication/source qualification separation,
multi-parent skill facets, optional HTML filters and native Word baseline.
Services are disabled unless explicitly enabled. This is an initial prototype.
